# 评测指南

用独立留出集比较规则、模型和二者组合：

```bash
source scripts/env.sh
bash scripts/evaluate.sh "$DEID_WORK/models/demo" \
  "$DEID_WORK/models/demo/best.bpk" \
  "$DEID_WORK/runs/my-data/test.jsonl" \
  "$DEID_WORK/runs/my-evaluation.json"
```

评测文件格式见[数据格式](data-format.md)。报告包含：

模型评测的单份文书上限为 512 token；超长文书应先分段并同步黄金区间，再评测。批量 predict 和单文件 redact 则使用重叠窗口处理长文本。

- 实体 precision、recall、F1：边界与类别必须同时完全匹配，并提供各类明细。
- 敏感字符遮盖率：黄金标注的敏感字符中，有多少被任意预测区间覆盖。
- 残留文书率：文书中任一黄金敏感字符未遮盖，即计为残留。
- 非敏感字符误遮盖率：作为文本信息损失的粗略指标。

模型和规则组合时对相交区间取并集，可能盖住更多隐私，也可能扩大误删。严格实体指标和字符指标应一起查看。长文书和高密度实体更容易出现至少一个漏点，跨数据集比较残留率时要说明文书分布。

JSON 中的 scope 表示带标注数据评测，不是程序对输入数据真实性的判断。自己的评测还需记录模型包哈希、程序版本、数据来源、标注规则、文书数量和数据哈希。不同模型应使用相同划分、实体定义与后处理口径。

建议人工检查姓名、机构、标识号、格式变体、长文本及无隐私负例。模型卡中的示例成绩只表示所述样本上的行为；用于自己的场景时，以独立复核的本地留出集为依据。
